= Migration from valentus-theme
:navtitle: Migration
:description: Inventory and steps to move Theme Demo content out of valentus-theme without duplicating guide docs.
:page-tags: migration, demo-data

Do **not** copy the entire `valentus-theme` repository.
Move only the *Theme Demo* slice (`docs/modules/ROOT/`) into this component and leave the *guide* module in `valentus-theme`.

== Component rename (`theme-demo` → `demo-pages`)

Baseline shared body fixtures use component name **`demo-pages`** (`docs/demo-pages/`).
The earlier name `theme-demo` was too theme-specific; published URLs and playbook `start_path` values changed in **v0.3.0**.

Consumers should pin `demo-data` @ `v0.3.0` (or newer), set `start_path: docs/demo-pages`, and allowlist `demo-pages` in `siteNavTree`.

== Sidebar nav (v0.3.3+)

Forest root label **Demo pages** comes from `antora.yml` `title` (component `name` stays `demo-pages`).
Under that root, `nav.adoc` groups **Core** (body fixtures + migration) and **Extensions** (overview, topic pages, optional supplements via `extensions-supplements-nav`).
Pin **v0.3.3** when you rely on this hierarchy; v0.3.1 briefly used the mistaken forest label **antora-core**.
Post-build redirect stubs on deployed demos map `/theme-demo/…` → `/demo-pages/…` for bookmarked Pages URLs.

== CSS / design language (do not duplicate)

Foundational tokens live in the Valentus UI bundle (`site-visual.css`, `--adt-*`).
Extension supplemental CSS should continue to *reference* those tokens with fallbacks — not fork palettes into demo-data.

* Chassis vs paint: link:https://github.com/antora-supplemental/valentus-theme/blob/main/CHASSIS.md[`valentus-theme/CHASSIS.md`^]
* Fixture-only classes (e.g. `.adt-logo-fixture-*`) stay in bundle CSS; demo pages keep using them

== valentus-theme playbook after migration

. `antora-playbook.yml` — guide + optional xref to external `demo-pages` source if you want fixtures on Pages without merging repos
. `antora-playbook-visual-demo.yml` — point `content.sources` at this repo's `docs/demo-pages` instead of sibling clone
+
When pinning a git *tag*, set `branches: []` on that source entry so Antora does not also collect `main` (duplicate `demo-pages` nav).
