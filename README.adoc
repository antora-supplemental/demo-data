= demo-data
:description: Shared Antora content components for theme and extension demo sites — not production hub docs.

ifndef::env-github[]
image:https://img.shields.io/github/license/antora-supplemental/demo-data.svg?style=for-the-badge[License]
endif::[]

Shared **Antora content sources** for demo and docs-preview sites in the `antora-supplemental` org.
Production org hubs keep their own product documentation; this repository holds reusable mock pages that exercise theme chrome and extensions.

Architecture: link:https://docs.antora-supplemental.org/docs/proposals/demo-data-catalog/[Demo data catalog proposal^].

== Three-layer model

[cols="1,3", options="header"]
|===
| Layer | Responsibility

| **Baseline** (this repo)
| Host-agnostic AsciiDoc fixtures — nav, xrefs, admonitions, tables, code, images, extension samples. Component `theme-demo` under `docs/theme-demo/`.

| **Extension supplements**
| Extra components or overlays when an extension needs shared smoke beyond its own `examples/docs`. Live here as `docs/fixtures/{scope}/` *or* stay in the extension until two demos reuse the same pages.

| **Compose playbooks**
| Consumer repos (`facto-stack`, `valentus-theme` visual demo, extension CI) add `content.sources` entries — baseline + stack-local pages + optional fixture sources. UI bundles and extension npm packages stay in their own repos.
|===

Generic syntax-only samples remain in link:https://github.com/antora-supplemental/antora-demo[`antora-demo`^] (`samples` component) for the org docs hub.

== Prescribed pattern (naming + layout)

=== Repository naming

[cols="2,3", options="header"]
|===
| Pattern | When

| `demo-data` (this repo)
| Default umbrella for baseline + org-wide fixtures.

| `demo-data-{scope}`
| Optional split when a fixture set is large, licensed differently, or versioned on its own cadence (e.g. `demo-data-valentus`). Prefer folders under `demo-data` until a split is justified.

| Extension repo paths
| `examples/docs/` or `fixtures/antora/` — *minimal* smoke for that extension's CI. Do not duplicate baseline pages; link to `theme-demo` in the playbook instead.
|===

=== Antora layout in this repo

[source,text]
----
docs/
  theme-demo/              # baseline component (antora.yml at component root)
    antora.yml
    modules/ROOT/...
  fixtures/
    README.adoc            # supplement index
    site-nav-tree/         # supplement: multiple component roots (see README inside)
      catalog-alpha/
      catalog-beta/
----

Each **component** is a directory with its own `antora.yml`.
A **supplement folder** may contain one or many components; playbooks use one `content.sources` entry per `start_path`.

=== `content.sources` snippet

Baseline only:

[source,yaml]
----
content:
  sources:
    - url: https://github.com/antora-supplemental/demo-data.git
      branches: main
      # Pin for reproducible CI (tag-only — set branches: [] to avoid duplicate nav):
      # tags: [v0.2.0]
      # branches: []
      start_path: docs/theme-demo
----

Baseline + extension supplement (same repo, second source):

[source,yaml]
----
    - url: https://github.com/antora-supplemental/demo-data.git
      branches: main
      start_path: docs/fixtures/site-nav-tree
----

Stack-local pages stay in the consumer (not copied here):

[source,yaml]
----
    - url: ./..
      start_path: demo/docs
      branches: HEAD
----

Monorepo / dev phase: replace git `url` with a relative path to a sibling clone — same `start_path` keys.

=== Publishing from an extension without duplicating baseline

. Keep *behavior* smoke in `{extension}/examples/docs` (single component, tiny nav).
. When a fixture is reused by `facto-stack` *and* another demo, add `docs/fixtures/{extension-name}/` here and document the playbook snippet in the extension README under *Demo data supplement*.
. Reference `theme-demo` for typography/tables/code — supplements should only add pages that prove the extension (multi-root nav, search-chat corpus, nav-typology labels, etc.).

=== Versioning

* Tag this repo with SemVer when component names, nav, or `start_path` layout changes (`v0.1.0`, `v0.2.0`, …).
* Demo playbooks may track `main` for preview or pin `tags: vX.Y.Z` for CI.
* Extension supplements in this repo share the same tag line as baseline unless split into `demo-data-{scope}`.

== Consumer: facto-stack demo

link:https://github.com/antora-supplemental/facto-stack[`facto-stack`^] `demo/playbook.yml` composes:

. `theme-demo` from this repo (git URL)
. `facto-stack` from `facto-stack/demo/docs` (Mermaid client, lightbox, SoftNav)
. `@antora-supplemental/facto-stack` `profile: demo` with `siteNavTree.include: [home, theme-demo]`

Optional: add the `site-nav-tree` fixture source and extend the allowlist — documented in the fixture README.
